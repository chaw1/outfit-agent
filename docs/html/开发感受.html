开发感受¶

这一节由 Gary 本人写。下面是提纲和过程里的关键节点（时间都在 docs/开发记录.md 里可查），写的时候挑自己真实有感触的说，不用面面俱到。

提纲¶

  1. 怎么拆的题：拿到手写需求后先做了什么（先实测模型能力再定架构，而不是先写代码）。
  2. AI 原生开发是怎么做的：我负责定目标、拍板和验收，Claude 负责调研、设计和验收，Codex 负责并行写后端和 App，Fable 做独立评审。分工方式、我在里面真正花精力的地方。
  3. 最有收获的一次纠偏：第一版"智能体"其实是关键词路由加模板句，测试全绿、看起来能用，是评审读代码才发现的。从这里得到的体会（测试通过 ≠ 做对了；要有人真的去看产出）。
  4. 最难的卡点：域名 HTTPS 被备案拦截（换端口也没用，最后用 IP 证书）；Mac 和服务器架构不同导致镜像起不来；改图"塞进裤腰"没做到却没人发现。
  5. 对"高还原"的理解：从吊牌被"穿"上身这件事看，还原不只是模型能力，还要靠工程上的质检和兜底。
  6. 如果再给一周：会先做什么（参考调研第 5 节）。

过程里的关键节点（供回忆）¶

  • 21:54 接到作业；22:08 前先实测模型能力：试衣 + 换景 14 秒、5 秒视频 52 秒，确定能力边界后才定架构。
  • 22:12 写好设计约定，前后端两个 Codex 按同一份约定并行开工；22:45 / 22:51 各自交付第一版。
  • 22:44 服务器域名被备案拦截（换端口也不行），改用 IP 证书。
  • 22:51 评审 + 读代码发现"阶段内是关键词路由"，开第二轮。
  • 23:31 线上真实全链路首次跑通（212 秒）；目检发现吊牌上身、改图没做到；你提出手机上的改图交互要做细。
  • 23:52 局部改上线：圈外像素逐像素不变；没做到会如实说。
  • 00:19 发现 App 从没连过线上服务，补联调。
