演示脚本（5–8 分钟）¶

iPhone 用数据线连 Mac，Mac 上打开"iPhone 镜像"或 QuickTime（文件 → 新建影片录制 → 选 iPhone）投屏。提前准备：一个已经走完全流程的项目（备用，防止现场生成慢），一个新项目现场跑；另开一个终端窗口连好服务器。

0. 一句话开场（20 秒）¶

"这是给小红书穿搭博主用的内容智能体。品牌方只给几张衣服图，博主在手机上和它聊，聊出场景和风格，先出脚本，确认后批量出图、局部改图，最后拿到能直接发的图文笔记和一条短视频。这是 MuseGate / Chiccify 那条链路的 mini 版。"

1. 新建合作（1 分钟）¶

  • 新建项目：品牌名、一句需求（"夏季新品，想要松弛感"），上传 2 张衣服图 + 1 张"我的照片"。
  • 智能体几秒内先给出衣服分析卡（品类、颜色、面料），接着给出 3 个方向；每个方向的灵感预览图随后陆续到齐（线上实测整段约 1 分钟，卡片先到、图后到）。
  • 讲点：衣服卡是 LangGraph 节点里直接流式推过来的，不用等整轮结束；预览图是明码标价的低成本层（约 0.5 元/张），批量出图要等脚本确认才花钱。

2. 多轮对话改脚本（1.5 分钟）¶

  • 选一个方向，出脚本（标题备选、封面、每个镜头的场景/动作/配文、视频分镜）。
  • 说一句"换成通勤风"——脚本被重写。
  • 现场实验 E4（时间旅行）：打开"历史版本"，恢复到通勤风之前那一版。
  • 讲点：阶段之间是状态机（代码管花钱和顺序），阶段之内是 ReAct（模型从当前允许的工具里自己选，"换成通勤风"没有任何关键词判断）；历史版本直接来自 LangGraph 的 checkpoint 历史。

3. 确认 → 出图 → 主动播报（1 分钟）¶

  • 确认脚本，图片陆续出来；全部完成后智能体主动发消息："5 张都好了，还原分 92–96"。
  • 讲点：生成在 Worker 里跑（Postgres 队列 SKIP LOCKED + 去重键），对话不卡；每张图生成后用看图模型对比原衣服打还原分，低于 60 自动修一版——回应"高还原是生死线"。

4. 手机上的改图交互（1.5 分钟）¶

  • 点图进全屏：双指放大看袖口、纽扣。
  • 局部改：涂抹吊牌或袖口 → 选"去掉吊牌"/"换个颜色"这类稳的改法 → 只改这一块；完成后拖对比滑块看前后。
  • 讲点：改完会用看图模型核对"改没改到位"。线上实测"把卷起的袖口放平"两次都没过——系统会如实标"未改到位"，第八轮起这种版本不会默认进笔记，要用户明确"仍然采用"；点"再试一次"是一次新的付费尝试，网络重放不会重复扣钱。主动展示一次失败，比只放成功例子更可信。
  • 讲点：服务端是"蒙版 → 裁剪 → 只改这一块 → 羽化贴回"，圈外像素逐像素不变，有测试证明；改完还会让看图模型核对"指令到底做到没"，没做到会如实说，并给"再试一次 / 换个说法"。
  • 长按另一张图 → 引用到对话 → "这张背景亮一点"，智能体知道指的是哪张。

5. 笔记与视频（1 分钟）¶

  • 选图排序 → 生成笔记 → 笔记预览：标题、分段正文、话题标签，底部显示这篇成本约 ¥x和 AI 生成声明。
  • 确认视频（单独确认，最贵的一步），约 1 分钟出 5 秒短视频。

5.5 管理端（40 秒）¶

  • 手机或电脑浏览器打开 https://47.97.153.127:8443/admin，输入口令：总览里刚才这一单的调用次数和花费已经进来了，最近 7 天趋势图和模型费用占比一眼能看出钱花在哪；用量统计按模型、按天看一眼；模型与配额页把出图模型换一个、把 free 层每日预算调一下，保存即生效，不用重启。
  • 讲点：这是运营面——注册登录背后有人能看用户、看用量、管模型分层和配额；花钱的动作在服务端按层级预算门禁，对话不受限；任务队列里失败的能重试。

6. 现场实验 E1：重启也不丢（30 秒，可选）¶

  • 在终端执行 ssh quanbot-ecs 'cd /opt/outfit-agent && docker compose -f compose.yaml -f compose.production.yaml -f compose.image.yaml restart api'，手机上继续发一句话，对话、脚本、待确认点都在。

7. 收尾（30 秒）¶

"框架选型、实验数据和反方意见在 docs/调研.md；开发全过程和每个卡点在 docs/开发记录.md——包括我自己的第一版被评审指出'阶段内是关键词路由、不是真智能体'之后怎么改的。"

设计系统 30 秒（电脑侧，接在主流程之后）¶

不在 App 内演示，也不连接线上。提前在电脑打开 设计系统文档 和 paper / 390、studio / 390 两张画廊截图；需要现场切换时，单独打开本地开发 URL http://localhost:19422/__design（端口可由 E2E_DESIGN_PORT 覆盖）。

  • 0–10 秒：来源。 打开 app/design/tokens.json 和生成的 app/src/theme.ts，指出颜色、间距、字体只有一份来源；Figma Brand/Primary 对应 color.brand.primary，改变量后运行脚本生成。
  • 10–20 秒：组件。 并排展示两张截图，指出同一组件的 paper / studio 主题，以及按钮四种变体与默认、按下、禁用、加载状态；补一句 320 / 390 宽度和 1.3 字号可以检查窄屏与大字布局。
  • 20–30 秒：回归。 展示四份 Playwright 基线与本次交付摘要中的实际验证记录，说明变量改动要经过生成一致性检查、lint、四组合快照和完整 mock 回归。画廊只在开发 URL 中存在，正式构建在路由上下文收集阶段排除。

讲述稿：“这套界面从 token 生成，两种主题共用组件规格。设计改变量，代码生成产物；每个组件展示变体和状态，用四组截图检查回归。画廊只给开发评审使用，App 没有入口，正式包在编译收集路由时就排除它。”

手工切换前，按设计系统文档关闭 CI 模式并启动本地 Expo 文件监听；运行 e2e 前关闭自己占用相同端口的手工服务，或覆盖测试端口。正式模式访问 /__design 应显示 Unmatched Route。

只展示本次实际跑出的记录；没有验证的真机、读屏或系统动态字体表现，直接说明尚未验证。

被追问时¶

问题 答法要点
为什么 LangGraph 不用手写？ 先承认 7 个阶段手写也能跑；选它是因为跨重启的状态、花钱前原生暂停恢复且重放不重复花钱、checkpoint 时间旅行、节点内流式——这些手写都要自己重造；第二名是 AgentScope
为什么对话用 DeepSeek Flash？ 这一步要的是快、选工具准、便宜；质量的大头在出图模型和还原质检
还原度怎么保证？ 提示词写入看图结果并要求保持版型/颜色/纽扣/口袋；生成后打分，低分自动修；吊牌等非服装部件明确忽略
生成失败、重复点击、服务重启怎么办？ 任务表去重键 + 租约 + 次数上限；结果未知的同步请求不盲目重发（避免重复扣钱）；E1/E2 实验
为什么用 IP 访问？ 域名未在阿里云备案接入，域名 HTTPS 被按 SNI 拦截；用 Let's Encrypt 的 IP 证书解决，每天自动续期
用量和成本怎么管？ 每次模型调用进账本（模型、耗时、估算费用、用户、项目）；管理端按模型 / 用户 / 天看；用户分 free / pro 层，每层每日预算，到限只挡花钱动作
怎么扩展到公司线上？ 见调研第 5 节：多智能体分工、专用试衣 + 精修、博主风格记忆、对接资产中心和点数计费
