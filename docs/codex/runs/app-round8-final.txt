做了什么
1. 每镜头默认选最新成功且核对通过的版本；未通过图显示“未改到位”，不自动入选。查看器与选图提供原因确认，approve_images 携带 accept_unverified；收到 unverified_image 后确认再重发。预览和发布清单标“手动采用”，保留旧草稿时也保留这个标记。
2. 改图使用 UUID attempt；同一次传输重试复用，明确“再试一次 / 换个说法”换新 attempt，保留原父图与选区。消费 job / done / pending_action.reused，显示“这次和上次一样，没有重新生成”，不再空等新 ID；首次状态读取失败、后续轮询才收到复用标记也覆盖。
3. note 阶段支持查看器“采用此版本到笔记”和笔记卡“重新选图”。同镜头原位替换并保持封面、顺序，重新 approve_images；干净预览与发布清单跟随 note.image_ids。video/done 保持定稿，迟到的 note 卡不会解锁。
4. 草稿保存 SHA-256 sourceFingerprint 与 dirty；干净草稿跟随服务端，冲突时提供“保留我的修改 / 采用新版本”，常驻“恢复服务端版本”。明确切换前备份本机修改，可恢复；兼容旧草稿。
5. REST 用 AbortController 分类超时：读 20 秒、写 60 秒、上传 120 秒，响应体接收也计时，写入不自动重放；创建超时先刷新项目列表，再让用户判断。所有上传入口显示“第 n/N 张”。SSE 保持 120 秒。
6. “换一组”旁显示服务返回的估价与“含 2–3 张预览”，轮询不丢估价；引导第二页标题已修改。新字段缺失时兼容旧服务。

确认层放在查看器自身 Modal 内，避免 iOS 同级 Modal 无法可靠呈现；返回键先取消确认并保留查看器。沿用现有主题 token 与提示组件，没有重做原有查看器交互。
假服务同步支持新字段、明确采用持久化、attempt 去重/复用、note 阶段重选与费用提示。app/README.md 已补“第八轮”。
