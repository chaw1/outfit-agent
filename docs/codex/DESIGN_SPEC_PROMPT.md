# UI 设计稿：衣序 App 高保真设计板

## 目标

产出一份"先设计、后实现"的 UI 设计稿，让评审者打开就能看懂整个 App 的信息架构、核心流程、视觉语言、每个页面的高保真样子和各种状态，以及组件规格。它是开发的上游依据：页面结构、文案口径、字段名都要与 `docs/设计.md`（§1.1 产品范围与分期、§8、§10–§16）一致，不要自创第二套说法。

交付两样东西：

1. **`docs/UI设计稿.md`**：设计目标与原则（片场是暗的、编辑桌是亮的；一次只问一个问题；花钱前先说清；错误要能恢复；用户只看点数）；信息架构（页面地图）；核心流程图（沉浸编导、一键出片、离开再回来与通知、账号闭环，用 mermaid）；视觉语言（两套主题 `studio` 深色片场 / `paper` 浅色编辑桌：色板、字体与字号阶梯、间距与圆角、动效时长、图片比例 3:4、AI 标识位置）；页面设计——每个页面一节：目标、布局、关键状态（空 / 加载 / 错误 / 成功 / 点数不足）、文案口径、配图（设计板截图）；组件规格表（Button / IconButton / Field / Chip / Segmented / Card / Badge / Sheet / StatePanel / Toast / ProgressStrip / ImageViewer / VersionBar：用途、props、变体、状态、尺寸）；可访问性清单（触控 44、对比度、动态字体、无障碍标签）；设计到开发的交付清单。
2. **`docs/design/index.html`**：单文件高保真设计板，纯 HTML + CSS（可少量 JS 做主题切换），无外部依赖，CSS 变量命名与 §16.1 的 token 一致（`--color-brand-primary` 等）。按流程排列手机框（390×844）展示至少这些页面：隐私提示与引导（3 页）、登录 / 注册（含同意勾选、恢复码展示）、首页（片场：灵感墙、进行中、我的片场）、拍一组新片（两种模式切换、三张卡、风格词条、开拍按钮带点数）、编导间（方向卡、脚本卡、确认按钮带点数、auto 模式的步骤进度与"我来接手"）、图片查看器（版本条、未改到位角标、涂抹局部改）、挑图与笔记预览（采用 / 手动采用标记、发布清单）、视频就绪、账号与安全（修改密码、恢复码、注销）、忘记密码、协议页。每个手机框旁边有标注（页面名、设计要点、状态变体）。灵感墙和示例图片用 `app/assets/inspiration/studio-01..10.jpg`（相对路径引用，复制到 `docs/design/assets/` 并压到 ≤ 200 KB/张）。
3. 用 Playwright 把设计板按页面截成 PNG 放 `docs/design/shots/`，在 `docs/UI设计稿.md` 里引用；README 文档表加一行"UI 设计稿"。

## 验收标准（Claude 会亲自实测，不信自报）

1. `docs/design/index.html` 用浏览器直接打开可看，无控制台错误，无外部网络请求；深浅主题切换有效；页面数 ≥ 12 个手机框。
2. `docs/UI设计稿.md` 每个页面小节都有截图、状态列表与文案口径；文案与 §14.5 的词汇表一致（拍一组新片 / 我的片场 / 编导间 / 出镜的人 / 开拍 / 点）；没有"¥ / 元 / 费用"。
3. 组件规格表覆盖上面列出的全部组件，每个组件至少写明变体与状态。
4. 交付摘要写到 `docs/codex/runs/design-spec-final.txt`（由 `-o` 指定）：做了什么、怎么验证、没做什么。
