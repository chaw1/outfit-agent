# 规划：固定模特库与人像一致性，以及对照 Chiccify Web 端还缺什么

写于 2026-10-21 晚。目的有两个：一是把「下一步怎么把人像一致性做扎实」想清楚，分期可执行；二是把我们这版 App 和霖润自家 Chiccify（桌面 Web）对照一遍，列清还缺哪些步骤和功能，排好优先级。竞品事实来源见 [调研-Chiccify对照.md](调研-Chiccify对照.md)，现状来源是本仓库代码。

## 0. 结论

1. 一致性现在靠三件事：博主本人照片当参考图进出图模型、封面当锚点、看图模型打「人像一致性 / 封面一致性」分。能用，但分数只报不拦，模特也不是一等资产。
2. 霖润的做法是「模特库必选 + 专属模特训练（LoRA）+ 换脸修脸（FaceFusion）+ 主图锚点 + 存证」。差距主要在**模特是一等资产**和**有后处理兜底**，不在生成模型本身。
3. 分三期补：一期（1–2 天）模特库 + 身份卡 + 多张参考 + 低分自动重出；二期（1 周）人脸后处理兜底 + 客观指标；三期（2–4 周）专属模特训练流水线。每期都有可测的验收线。
4. 对照 Chiccify Web 端，我们缺的主要是：每个方向多组真图可选、完整的小红书发帖表单与草稿箱、修图小工具矩阵、视频分镜模板、自动发布助手、资产中心。其中前两项值得先补，后面几项是产品边界问题，不是能力问题。
5. 我们一套代码可以直接出 Web 版（Expo Web，mock 回归就是在浏览器里跑的），「有没有 Web 端」不是差距，缺的是部署和桌面布局。

## 1. 现状：我们现在怎么做一致性

| 环节 | 现在的做法 | 在哪 |
|---|---|---|
| 模特来源 | 博主在「我的形象」上传本人照片（最多 20 张），或把满意的成片「存为模特」；新建片时选一张当出镜的人 | `app/src/components/ProfileEditor.tsx`、`server/app/assets_library.py` |
| 出图参考 | 每一镜把「模特照 + 这一镜的衣服图」一起作为参考图传给出图模型，提示词写「保持参考图中模特身份」 | `server/app/workflow.py` 出图节点 |
| 封面锚点 | 先出封面；其余镜头把封面成片追加为最后一张参考图，提示词写「以封面为锚点，同一人、同一妆发、同一光线」 | `server/app/worker.py` |
| 核对 | 每张成片用看图模型打三类分：还原分（衣服）、人像一致性（本人照片 vs 成片，只看面部身份）、封面一致性（封面 vs 成片） | `server/app/providers.py` `fidelity()` |
| 兜底 | 还原分低于 60 自动重出一版；**人像一致性分只汇报不拦截** | `server/app/worker.py` `_auto_fix()` |
| 管理端 | 看图 / 出图 / 视频模型可切 | 管理端 · 模型与配额 |

真实数据：10-21 晚 run-5（Seedream 5.0 pro）封面一致性稳定，人像一致性在同一组片里波动，换场景后脸会「像但不是同一个人」。这正是只靠参考图的通病。

## 2. 霖润怎么做（公开信息）

| 做法 | 说明 | 来源可信度 |
|---|---|---|
| 模特库必选 | 「模特只能从模特库选择」：Chiccify 模特 / 我的专属模特 / 收藏 / 外部模特 / 人台 | 官方页面文案 |
| 专属模特训练 | 上传照片 → 训练中 / 审核中 → 可用；代码里是 FLUX LoRA（步数 4000、lr 2e-4、rank 32） | 代码包字符串 + 早前登录笔记 |
| 换脸 / 修脸 | FaceFusion；ChicGuru 有「换脸」「视频修脸」工具 | 代码包字符串 |
| 主图锚点 | 定主图后「以此为基调」出全套 | 官方页面文案 |
| 存证 | 专属模特「自动上链存证」「允许平台代理维权」 | 官方页面文案 |
| 质量口径 | 「高还原是生死线」；没有公开任何人脸一致性数字 | 媒体 |

要点：他们把**模特当资产**管，把**一致性当后处理**做，生成模型（Chic-Image）负责审美和服装还原，不指望它一次把脸画对。

## 3. 目标指标

| 指标 | 怎么算 | 目标 |
|---|---|---|
| 人脸相似度 | ArcFace 向量余弦相似度，成片人脸 vs 身份卡正脸 | 同一组片每张 ≥ 0.60（一般认定为同一人的阈值），均值 ≥ 0.70 |
| 人像一致性分 | 现有看图模型打分，保留做可读解释 | ≥ 70 才默认入稿 |
| 一次通过率 | 不触发重出就达标的比例 | 一期 ≥ 70%，二期 ≥ 90% |
| 人工盲评 | 10 组片各 6 张，两人盲评「是不是同一个人」 | 二期 ≥ 90% 判同一人 |
| 成本 | 每张额外花费 | 一期 0（只多传参考图），二期 ≤ 0.2 元/张（本地 GPU） |

## 4. 分期方案

### 一期（1–2 天）：模特库成一等资产，参考图从「一张」变「一套」

做什么：

1. **模特表**：新建 `models` 表（id、user_id、name、kind：preset / own / generated / trained、status、identity_text、face_asset_id、sheet_asset_ids、created_at）。现有「我的形象」照片和「存为模特」自动迁移成 kind = own / generated。
2. **预置模特库**：把已经生成好的 3 位模特（模特 A / B / C）做成 preset，每位一套「身份卡」：正脸特写、全身正面、四分之三侧身、半身微笑，共 4 张，同一人同一光线，用 Seedream 多参考一次生成。
3. **身份卡文字**：每位模特建卡时用看图模型写一段 identity_text（脸型、眉眼、鼻唇、肤色、发型发色、身高体态、年龄段），存起来，不再每次重写。
4. **出图参考改成一套**：每一镜参考图 = 正脸特写 + 全身 + 这一镜的衣服 +（非封面时）封面成片；提示词带 identity_text。顺序固定：人物在前、衣服在中、封面在最后。
5. **低分自动重出**：人像一致性分低于 70 时自动重出一版（复用现有 `_auto_fix` 的幂等键和预算门禁），重出时参考图加上「上一版里脸最像的那张」。
6. **App**：新建页「出镜的人」改成模特选择器（衣序模特 / 我的模特 / 本次上传），设置里「我的形象」可以给本人照片建身份卡（一键生成缺的角度，花 3 张图的钱，先确认）。

验收：

- 同一组片 6 张成片，人像一致性分全部 ≥ 70；run 记录进 `docs/验收与部署.md`。
- 预置模特可选可用，不上传照片也能出整组片。
- 迁移后老项目正常打开。

### 二期（1 周）：人脸后处理兜底 + 客观指标

做什么：

1. **人脸服务**：Windows 3060 上起一个小服务（FastAPI），两件事：`/similarity`（InsightFace ArcFace 向量 + 余弦）、`/refine`（inswapper 换脸 + CodeFormer 修复，只动脸部区域，输出前后对比）。ZeroTier 内网可达，服务端通过 provider 接口调用，管理端可开关。
2. **质检改成两道**：先算 ArcFace 相似度（毫秒级、不花钱），低于 0.60 才进「重出 / 换脸」分支；看图模型打分保留，只用来给博主写可读的差异说明。
3. **兜底策略**：重出一次仍不达标 → 用成片做换脸修复 → 再算相似度 → 达标入稿，并在成片上标「脸部已修」；不达标就老实说，保留原版让博主决定。
4. **A/B**：管理端加开关（只参考图 / 参考图 + 换脸兜底），用量统计按开关分组，方便看一次通过率和成本。
5. **隐私**：本人照片的人脸向量只存本地，不出 ECS；换脸只用于博主自己的模特，接口校验 owner。

验收：

- 10 组片人工盲评 ≥ 90% 判同一人；一次通过率 ≥ 90%。
- 换脸路径平均 ≤ 8 秒 / 张，成本 ≤ 0.2 元 / 张（电费口径）。

### 三期（2–4 周）：专属模特训练流水线

做什么：

1. **训练任务**：上传 10–20 张本人照片 → 自动人脸裁剪、去重、打标（看图模型写 caption）→ LoRA 训练（Z-Image 或 FLUX，3060 12G 可训 rank 16–32，约 40 分钟）→ 自动出 4 张测试图算相似度 → 人工审核 → 状态可用。走现有 Postgres 队列，kind = train。
2. **出图路径**：自托管 ComfyUI（已有 fashion-ai 那套）接成第三个出图 provider，trained 模特强制走它；云上出图模型（Seedream）继续服务 preset / own 模特。
3. **存证**：训练集和 LoRA 文件做 SHA-256，写进 models 表和一条审计记录；要不要上链看业务，技术上一个接口的事。
4. **成本与配额**：训练算 200 点一次，进现有账本与每日预算；管理端可看训练队列。

验收：

- 专属模特 10 组片盲评 ≥ 95% 判同一人，相似度均值 ≥ 0.75。
- 训练任务失败可重试、可取消，App 退后台不影响。

### 不打算做的

- 自研或微调出图大模型：一致性问题用「资产 + 后处理」解决更便宜，出图模型交给云厂商或接 Chic-Image。
- 视频里的人脸一致性：先把图做稳，视频修脸放到视频分镜那一期一起考虑。

## 5. 对照 Chiccify Web 端：我们还缺的步骤与功能

「我们现状」按 2026-10-21 晚的 App 填；「缺什么」只写差距，不写已经有的。

| 环节 | Chiccify（桌面 Web） | 我们现状 | 缺什么 | 建议 | 优先级 |
|---|---|---|---|---|---|
| 素材三槽位 | 服饰图必填、模特图必填（只能从模特库选）、参考图选填 | 衣服必填、出镜的人选填、参考图选填 | 模特库作为必选入口 | 本规划一期 | 高 |
| 确认图片角色 | Agent 问「哪张是服饰、哪张是模特」 | 上传时按槽位区分，不用问 | 无 | 不做 | — |
| 选灵感 | 每方向多组真图可挑、带参考图发散 | 每方向 1 张预览图 + 首页灵感墙 10 张 | 每方向 3 张可选，选中那张成为封面基调 | 方向节点一次出 3 张，预览卡横滑 | 高 |
| 定主图 | 选中后融入服饰和模特生成主图 | 先出封面，再出其余 | 「主图只读槽位」的概念 | 封面卡标「主图」，锁定不参与改图 | 中 |
| 收全套 | 以主图为基调自动策划 | 封面锚点 + 脚本 | 无 | — | — |
| 一键出片 | 全自动、参考图必填 | 全自动、可接手、有收尾卡 | 无 | — | — |
| 过程透明 | 思考过程 / 使用能力 / 耗时 / 花费 / 来源图 | 每条回复可展开工具、耗时、点数、分步 | 来源图 | 展开栏加「用了哪几张参考图」缩略图 | 低 |
| 方案面板 | 分镜列表可增删改、撤销重做、标题文案点字即改 | 脚本对话改 + 每镜四个快捷动作 + 版本历史 | 点文字直接改 | 脚本卡字段长按进入编辑 | 中 |
| 修图工具 | 消除笔、局部重绘、换头、换背景、去皱、扩图、高清、换色 | 对话圈选局部改 + 核对 | 换背景、扩图、高清 | 三个最常用的做成查看器里的快捷动作，复用局部改链路 | 中 |
| 视频 | 5/10 秒、首尾帧、音效、分镜模板、多模型 | 单图 5 秒 | 分镜模板、10 秒 | 先做「用入稿图顺序串成 10 秒」 | 中 |
| 发布面板 | 小红书发帖表单：标题字数、正文、合集、地点、原创声明、草稿箱 | 笔记预览可编辑、本地草稿、发布清单、系统分享 | 标题 20 字计数、话题 chips、原创 / AI 声明勾选 | 预览页加这三样 | 高 |
| 自动发布 | 本地桌面助手扫码发小红书（灰度） | 系统分享接手 | 自动发帖 | 不做；写明平台政策与风险 | 低 |
| 模特库 / 专属模特 | 模特库、训练、存证 | 我的形象、存为模特 | 见第 4 节 | 本规划 | 高 |
| 资产中心 | 文件夹、标签、批量上传、自动打标、货号 | 素材库（模特 / 衣服 / 成片 / 短片） | 标签与自动打标 | 衣服上传时看图模型已出分析，存成标签即可检索 | 低 |
| 历史会话 | 置顶、重命名、删除、回收站、归档 | 列表、搜索、阶段筛选、删除 | 重命名、置顶 | 长按菜单加两项 | 低 |
| 实时通道 | WebSocket + 断线恢复 | 流式响应 + 轮询 | 无感知差异 | 不改 | — |
| 计费 | 缪斯点按张、提交前预估、失败退点 | 点数、每步预估确认、失败不扣 | 充值 | 接支付即可 | 低 |
| 水印 | 官方 / 商家 / 无水印三选 | AI 角标 + 元数据 | 商家水印 | 不做 | — |
| 端 | 桌面 Web，移动端受限 | iPhone App（Expo，同一代码可出 Web） | 部署一个 Web 版 + 桌面宽屏布局 | `expo export --platform web` 挂到现有 Nginx，宽屏时两栏（左对话右成片） | 中 |

排一下，值得先补的四件：**模特库（一期）**、**每方向多张灵感图可选**、**发布面板三样**、**Web 版部署**。这四件加起来大约三天。

## 6. 面试里怎么讲（三句）

1. 「一致性我现在靠参考图 + 封面锚点 + 看图模型打分，分数已经在成片上；下一步是把模特做成资产、加人脸后处理兜底，再做专属模特训练，这三步我已经排好了验收线。」
2. 「和 Chiccify 对照，流程主干是同构的，差在模特库和发布表单这两处，我排在最前；修图工具矩阵和自动发布是产品边界，不是能力问题。」
3. 「我这套是手机端全链路，Expo 同一代码能直接出 Web，桌面版只是布局和部署的事。」
