# 衣序 DS 设计系统

衣序 DS 把片场与编辑桌的视觉约定收敛到 token、组件规格和截图回归。范围以 [设计契约第 16 节](设计.md#16-设计系统衣序-ds) 为准；业务页面通过原有 `components/ui.tsx` 引用组件，该文件保留为 `components/ds/` 的再导出层。本文按 2026-10-21 的本地实现校对，部署与设备验收另见开发记录。

## 设计原则

1. **片场是暗的，编辑桌是亮的。** `studio` 承载拍摄与创作氛围，`paper` 承载阅读、编辑与确认；同一组件共享结构，用语义色板表达环境。
2. **一次只问一个问题。** 用标题、主操作和留白建立顺序。组件提供层级，页面决定当前需要用户完成的动作。
3. **花钱前先说清。** 点数、生成范围和确认操作要放在同一决策区域；加载或禁用状态要表达请求正在处理，避免重复操作。
4. **错误要能恢复。** 错误说明与重试、返回或换一种方式的操作相邻；失败状态不能只靠红色表达，也不能覆盖用户已输入的内容。

App 首页、素材库和新建页使用 `studio`，工作台与笔记编辑使用 `paper`；管理端的信息密度更高，沿用 `paper`。统一的是品牌、语义色、控件状态和交互规则，各场景保留适合自己的信息层级与布局。App 的原生组件与管理端 HTML 使用各自的渲染实现，通过同一份 token 源文件保持一致。

## Token 单一来源

源文件是 [`app/design/tokens.json`](../app/design/tokens.json)，使用 DTCG 格式：每个 token 包含 `$type`、`$value` 和说明用途的 `$description`，复用值可写成 `{color.paper.red}` 这样的引用。颜色使用 sRGB 分量和透明度，尺寸和时长带单位；生成时转换成 React Native 使用的数值与字符串。

[`app/scripts/build-tokens.mjs`](../app/scripts/build-tokens.mjs) 同时生成 [`app/src/theme.ts`](../app/src/theme.ts) 和 [`server/app/admin_static/tokens.css`](../server/app/admin_static/tokens.css)，[`app/scripts/build-token-docs.mjs`](../app/scripts/build-token-docs.mjs) 从同一份 JSON 生成下方 token 表。`npm run tokens` 统一更新三个产物，`npm run tokens:check` 检查三者是否与来源一致。`theme.ts` 标有“由 tokens.json 生成，勿手改”，继续导出已有的 `colors`、`studio`、`space`、`radius`、`type`、`motion`、`layout`，保留页面的使用方式；生成产物均可重复构建，不接受手工修补。

管理端加载 `/admin/tokens.css`，管理端未启用时该路径同样返回 404。CSS 变量使用短横线命名，例如 `color.paper.action` → `--color-paper-action`、`layout.touch` → `--layout-touch`。页面内部的 `--accent` 等语义别名引用这些生成变量；品牌调整从源 token 发起，不在管理端维护另一份颜色常量。尺寸与动效分别保留 `px` / `ms` 单位，平台字体由各端按系统支持设置。`app/tests/tokens.test.ts` 覆盖管理端 CSS 漂移检测及同一次颜色修改同时反映到两端产物。

| 分组 | 负责的约定 | 使用边界 |
|---|---|---|
| `color.paper` / `color.studio` | 浅色编辑桌、深色片场的文字、背景、边界与状态色 | 按语义取色，不在页面写颜色常量 |
| `color.brand` | 品牌级操作语义 | 设计变量与代码名称一一对应，兼容已有运行时导出 |
| `space` | 内容间距、内外边距与触控扩展间距 | `margin` / `padding` / `gap` / `hitSlop` 等从这里取值 |
| `radius` | 控件与容器圆角 | 同层级表面复用同一档圆角 |
| `type` | 字号、行高、字重、字间距及平台字体 | 组件从字体角色取值；画廊倍率同步作用于字号和行高 |
| `motion` | 交互与入场、骨架动画时长 | 动效需要考虑系统“减少动态效果”设置 |
| `layout` | 最小触控尺寸、内容最大宽度、缩略图比例 | 触控目标至少 44 × 44 逻辑尺寸 |

## 组件规格与清单

### 关键 props 与交互约束

- `Button({ title, onPress, variant?, disabled?, loading?, icon? })`：`title` 是可见文案，也是无障碍名称。加载时显示指示器，并与禁用态一起阻止重复触发；宽度至少 44，高度至少 52。`previewPressed` 仅用于固定展示按下态，普通页面通过实际按压触发反馈。
- `IconButton({ name, label, onPress, testID? })`：前三个 props 必填。`label` 描述动作，例如“关闭预览”，不能只写图标名称；`testID` 仅用于自动化定位。`hitSlop` 补充触控容错，控件自身仍保持 44 × 44。
- `Field({ label, error?, disabled?, inputRef?, ...textInputProps })`：`label` 必填，不能用 placeholder 代替标签。`error` 显示可见说明，并设置原生 `accessibilityHint`；Web 当前未建立 `aria-describedby` / `aria-invalid` 字段关联，仍需单独评审读屏表现。`disabled` 禁止编辑并显示半透明外观，在 Web 提供禁用语义；旧页面的 `editable={false}` 刻意保留 Web `readonly` 行为，不增加半透明样式，两者不能视为完全同义。普通聚焦沿用平台表现，`previewFocused` 用于画廊固定展示聚焦外观。
- `Chip({ label, onPress, selected?, disabled? })`：以 checkbox 语义公布选中和禁用状态。`Segmented<T>({ label, options, value, onChange })`：分组名称必填，每个选项必须有稳定 `value` 和可读 `label`，以 tablist / tab 公布当前选项；每个触控选项至少 44 × 44。
- `Sheet({ label, visible, onClose, children, inline?, closeLabel? })`：标题、关闭动作、遮罩关闭和系统返回共用明确的退出路径，内容区域统一处理滚动、安全区和键盘点击。`closeLabel` 允许业务使用明确的关闭名称；可选 `testID` / `closeTestID` 供自动化定位。`inline` 只把同一份表面放到画廊中，便于截图；业务弹层使用模态形态，减少动态效果开启时关闭滑入动画。
- `Toast({ text, tone?, onDismiss?, duration? })`：默认 `duration={6000}`，保持业务临时反馈的消失时机。`duration={0}` 仅用于画廊持续展示三种语气，避免长截图中示例提前消失；普通提示以 `status` 角色提供结果反馈，危险提示使用 `alert`。
- `ThemeProvider({ tone?, fontScale?, children })`：`usePalette()` 读取语义色板，`useTypography()` 读取字体角色。画廊的 `1.0` / `1.3` 同时缩放字号和行高，用于检查布局；它不替代 iOS / Android 系统动态字体与读屏验证。`Page` 为兼容既有页面默认使用 `tone="paper"`，会覆盖外层的主题；在 `studio` 提供器内嵌套 `Page` 时仍需显式传入 `tone="studio"`。

布局容器没有操作时不强加按钮角色。可交互元素需要可读名称，由上述必填 `title` / `label` 类型约束支持；图片是否需要描述由内容语义决定，信息图片提供 `accessibilityLabel`，纯装饰图片不抢占朗读顺序。

### 业务中的复用与设计判断

基础组件解决共同的展示与操作行为，业务页面负责选中、确认、保存和恢复的时机。`Page`、`Header`、`Button`、`Field`、`Notice` 等已用于实际页面；`ScriptViewer` 和 `ScriptHistory` 通过 `Sheet` 展示当前脚本和历史版本，共用固定标题与关闭按钮、最大 90% 高度、内容滚动、安全区和减少动态效果处理。组件画廊用于逐项比较变体，真实业务回归负责验证这些变体在任务中是否正确触发。

| 场景与问题 | 交互约束 | 对应实现与回归 |
|---|---|---|
| 点选灵感后直接进入下一步，用户不确定选中了什么 | 先展示选中态，再由明确的确认按钮推进；提交反馈与最终结果分开 | `DirectionsCard`；`app/e2e/script-viewer.spec.ts` |
| 新建表单较长，错误滚出当前视口 | 失败说明紧邻固定的提交操作；保留当前输入，供用户修正 | `Notice` + `Button`；`app/e2e/form-feedback.spec.ts` |
| 保存期间还能修改字段，成功提示对应的内容不清楚 | 提交中锁定相关字段；保存完成后继续编辑立即撤下旧成功提示 | `ProfileEditor` 的 `Field` / `Toast`；`app/e2e/form-feedback.spec.ts` |
| 完成卡片长期显示红框，用户分不清是否有新内容 | 红框只表示尚未看过的新结果；查看后恢复普通边框，新一批结果重新高亮 | 首页完成卡片；`app/e2e/completion-read.spec.ts` |

上述用例验证用户任务和状态变化；测试是否通过以本次运行记录为准。共享组件与 token 之外，原生相册、读屏、键盘和手势仍需设备验证。

## 开发画廊与截图回归

画廊通过开发 URL `/__design` 打开，App 内没有入口。顶部可切 `paper` / `studio`、宽度 `320` / `390`、字号倍率 `1.0` / `1.3`；20 个公开组件按用途合并成 13 个示例分组，展示变体与状态，主题提供器由顶部预览设置体现。

开发态使用 `__DEV__` 门控。正式构建还在编译 Expo Router 的 `_ctx` 模块时，从 `require.context` 的文件过滤表达式排除根 `__design` 页面、平台变体和 `__design/` 子目录；生产包不依赖“打开页面后再返回空内容”隐藏画廊。原有路由正则、平台过滤与特殊 HTML / API 文件过滤保持原有语义，业务路由不增加画廊入口。正式 Web 模式直接访问 `/__design` 的预期结果是 Expo Router 的 `Unmatched Route` 页面，不是跳转到登录页。

[`app/e2e/design-system.spec.ts`](../app/e2e/design-system.spec.ts) 的四个组合是 `paper` / `studio` × `320` / `390`。基线 PNG 位于 [`app/e2e/__snapshots__/`](../app/e2e/__snapshots__/) 下，文件名固定为 `paper-320.png`、`paper-390.png`、`studio-320.png`、`studio-390.png`，不带平台后缀，必须随变更提交。面向评审与文档的截图另存到 [`app/screenshots/ds/`](../app/screenshots/ds/) 的 `paper-320.png`、`paper-390.png`、`studio-320.png`、`studio-390.png`。字号 `1.3` 用于额外检查换行、裁切和触控区域，不应以更新四份基线替代检查。

四份像素基线在 macOS 本机浏览器生成，使用系统字体。测试仅在 macOS 执行像素比对和更新；Ubuntu CI 仍运行四组合的结构、ARIA 状态、页面错误与无 API 请求检查，生成实际截图并附到 Playwright 报告，也运行 1.3 字号、44 触控、Sheet 和正式路由检查。Linux 的字体和浏览器环境不同，当前没有 Linux 像素基线；增加该覆盖时需在固定的 Linux 字体与浏览器环境单独生成、评审基线。CI 的 App 检查已显式加入 `npm run tokens:check`，同时校验主题和文档表。

### 本地命令

以下命令均在仓库的 `app/` 目录、Node 22 环境执行。依赖和浏览器已经就位，不需要重新安装。端口与 API 地址全部指向本地，命令不接线上服务。

```sh
cd app
export PATH="$HOME/.local/share/mise/installs/node/22.23.1/bin:$PATH"
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/browsers"
export E2E_WEB_PORT="${E2E_WEB_PORT:-19420}"
export E2E_MOCK_PORT="${E2E_MOCK_PORT:-19421}"
export E2E_DESIGN_PORT="${E2E_DESIGN_PORT:-19422}"
export EXPO_PUBLIC_API_BASE="http://localhost:${E2E_MOCK_PORT}"

npm run tokens
npm run tokens:check
npm run verify
npx playwright test
```

业务 mock 回归、假服务和开发画廊分别使用 `19420`、`19421`、`19422`。需要避让已有进程时，提前设置对应环境变量覆盖端口，保持三个端口互不冲突。Playwright 配置负责启动对应的本地服务；业务回归与画廊分开构建，避免生产模式服务误用成开发画廊。

手工评审时，在另一个终端进入 `app/` 并沿用相同 Node 与环境变量，关闭 CI 模式以启用文件监听，再启动开发画廊：

```sh
unset CI
BROWSER=none npx expo start --web --host localhost --port "$E2E_DESIGN_PORT"
```

随后通过本地浏览器访问 `http://localhost:19422/__design`；覆盖端口后使用对应端口。画廊使用静态组件示例，业务交互验证仍使用本地 mock。Playwright 的两套 Expo 服务均设置 `reuseExistingServer: false`，不会复用手工启动的服务；运行 e2e 前，应关闭自己启动的 Expo 服务，或先覆盖对应的 `E2E_WEB_PORT` / `E2E_DESIGN_PORT`，避免占用相同端口。

确认为预期的视觉变更后更新基线，再完整复跑：

```sh
npx playwright test e2e/design-system.spec.ts --update-snapshots
npm run verify
npx playwright test
```

`verify` 依次执行 8 项检查：token 生成一致性、TypeScript、ESLint、单元测试、iOS 导出、Android 导出、Web 导出、画廊正式产物排除。最后一项通过 [`check-design-export.mjs`](../app/scripts/check-design-export.mjs) 逐文件读取三个平台产物，包括 Hermes 二进制，检查画廊路由与页面标记。完整 Playwright 回归同时覆盖已有业务 spec 与新增画廊 spec。

如需独立复查已经导出的产物，可以运行：

```sh
node scripts/check-design-export.mjs dist/ios dist/android dist/web
rg -a --no-ignore -l '__design|YIXU_DS_GALLERY_ONLY' dist/ios dist/android dist/web
```

脚本检查通过时退出码为 `0`；`rg` 预期没有命中，退出码 `1` 表示未找到，其他失败不能当作通过。`-a` 保证搜索二进制，`--no-ignore` 防止 `.gitignore` 跳过导出目录，不按文件扩展名缩小范围。实际导出、检查命令与退出码统一记录在[交付摘要](codex/runs/app-design-system-final.txt)中。本文给出复现方法，不把命令存在视为验证已经通过，也不据此推断真机表现。

## 无障碍评审清单

以下条目是每次组件或 token 变更的评审项，不表示本次已经完成真机验收。

- [ ] 可交互目标至少 44 × 44；密集图标之间保留可辨识的触控空间，320 宽度下不重叠。
- [ ] 按钮、输入框、图标操作、选项分组、选项和弹层有明确名称；读屏不会只读出图标名或 placeholder。
- [ ] `disabled`、`busy`、`checked`、`selected` 等状态与实际交互一致；加载时不能重复触发操作。
- [ ] 文字和边界在两个主题下可辨识；警告、成功与错误同时使用文本或图标表达，不只依赖颜色。
- [ ] 键盘 Tab 顺序、可见聚焦样式和操作可达性正确；弹层关闭后焦点能返回合理位置，遮罩与返回键都有关闭路径。
- [ ] 输入错误关联到对应字段，提示说明恢复方式；重要错误能够被读屏感知，短暂提示不夺取焦点。
- [ ] 宽度 320 / 390、字号倍率 1.0 / 1.3 下没有关键内容被裁切，按钮标签可以换行或完整展示。
- [ ] 系统减少动态效果时，入场、骨架与进度动效不会造成持续干扰；图片淡入等剩余动效另行检查。
- [ ] 信息图片有描述，装饰图与单块骨架不重复朗读；加载结构和进度有整体说明。
- [ ] iOS VoiceOver、Android TalkBack 和系统动态字体的实际表现单独验证、单独记录证据。

## 与设计协作

新增组件按“设计稿 → props / 变体 / 状态规格表 → 实现 → 实验室截图回评”推进：

1. 先明确页面用途、已有组件可复用的部分及主题差异，在 Figma 使用对应变量。
2. 在实现前写出 props、默认值、必填名称、可交互状态、触控尺寸与恢复行为；确认需要展示哪些变体，不把业务流程写进基础组件。
3. 在 `components/ds/` 实现并从 `index.ts` 导出，更新画廊分组。已有页面保持通过 `ui.tsx` 引用，避免为组件拆分批量改业务导入。
4. 在四个主题 / 宽度组合中比较截图，额外检查 1.3 字号和键盘、读屏行为；将差异与设计稿逐项核对。
5. PR 附变量或规格变更说明、预期截图差异与实际验证证据。设计反馈以 token 或组件规格为落点，避免把临时数值散落到页面。

## 变更与评审流程

token 改动 → 运行生成脚本 → 检查生成 diff → 更新四份视觉快照 → 完整回归 → 评审。

| 阶段 | 需要检查的内容 | 随变更提供的材料 |
|---|---|---|
| 修改来源 | token 类型、描述、主题语义、Figma 映射与引用是否完整 | `tokens.json` diff 与修改理由 |
| 生成产物 | `tokens` 可重建，`tokens:check` 能发现手改漂移 | `theme.ts`、管理端 `tokens.css`、本页 token 表的生成 diff |
| 组件状态 | 新值是否覆盖两种主题、必需变体和异常状态 | 更新后的规格表、画廊示例 |
| 四份快照 | 逐张确认变化是否由本次改动导致，避免无解释地接受差异 | `e2e/__snapshots__/*.png` 与 `screenshots/ds/*.png` |
| 工程回归 | `verify`、全部 mock Playwright spec、正式包排除与 lint | 命令、时间、退出码及证据路径 |
| 合入评审 | 设计意图、无障碍影响与业务页面渲染是否一致 | 可复现命令、已知限制、必要的人工检查记录 |

ESLint 的两条本地规则在 `src/` 内以 error 拦截裸十六进制 / RGB / HSL 色值与魔法间距，仅 `src/theme.ts` 和 `src/components/ds/` 豁免。规则见 [`design-tokens.cjs`](../app/scripts/eslint/design-tokens.cjs)，用例见 [`design-tokens.test.cjs`](../app/tests/design-tokens.test.cjs)。`npm run lint` 使用 `--max-warnings=0`，现有 import 排序告警也已清理。页面从 theme 取值；组件目录仍优先使用 token，不能作为新增独立色板的理由。

间距检查覆盖 `margin` / `padding` 及方向变体、`gap` / `rowGap` / `columnGap` 和 `hitSlop`，支持直接字面量、常量别名与静态对象成员。不把宽高、透明度、业务计数、比例或请求时长当作间距，也不把条件判断和业务 helper 的数字参数当作间距输出。这是源码规则，不是全程序数据流证明：动态属性名、可变绑定、解构别名及导入值的来源仍须评审。实际零违规结果以[交付摘要](codex/runs/app-design-system-final.txt)为准。

基线只在明确的视觉变更中更新。若只是拆分文件或调整导出结构，已有业务截图应保持一致；如果截图失败，先解释和修复原因，再决定是否更新。实际通过情况和遗留项统一记录在 [`docs/codex/runs/app-design-system-final.txt`](codex/runs/app-design-system-final.txt)。
