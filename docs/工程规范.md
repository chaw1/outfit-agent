本规范落实 [设计第 17 节](设计.md#17-第十一轮-b工程规范2026-10-21-1015只增不改可与其他轮并行)，与 [贡献指南](../CONTRIBUTING.md) 配套。接口契约仍只有 `docs/设计.md`。下文区分已有实现、门禁要求和待治理债务；设计记录不等于功能已上线。

## 目录与分层

| 路径 | 职责与依赖方向 |
|---|---|
| `app/src/app/` | Expo Router 页面，组合组件和 Hook，路由不直接实现供应商调用 |
| `app/src/components/`、`app/src/theme.ts` | 共享交互组件、颜色/间距/字体/动效 token；`ui.tsx` 提供 Page、Button、Field 等基础组件 |
| `app/src/hooks/`、`app/src/context/` | 工作台同步及会话状态；`useWorkspace.ts` 合并 SSE 与轮询结果 |
| `app/src/api/`、`app/src/lib/` | API 类型、HTTP/SSE 客户端与合并逻辑；选图、草稿、发布等可独立测试的逻辑 |
| `app/mock-server/`、`app/tests/`、`app/e2e/` | 本地假服务、Node 单测、Playwright 流程；线上测试使用独立配置 |
| `server/app/main.py`、`schemas.py`、`security.py` | HTTP/SSE 入口、Pydantic 输入输出、身份与归属检查 |
| `server/app/graph.py`、`workflow.py` | LangGraph 持久化与阶段工具放行，业务确认和幂等入队由代码控制 |
| `server/app/providers.py`、`worker.py` | 模型适配与 Mock；独立任务领取、租约、执行、结果回写 |
| `server/app/models.py`、`db.py`、`server/alembic/` | SQLAlchemy 表/会话与版本化迁移；checkpoint 由 PostgresSaver 管理 |
| `server/app/observability.py`、`log_errors.py`、`rate_limits.py` | 请求/模型事件、异常脱敏、共享限流 |
| `server/tests/`、`server/scripts/` | 单元/HTTP/迁移测试与闭环脚本；测试工具不作为生产 API 的依赖 |
| `server/deploy/`、`.github/workflows/ci.yml` | Compose 部署覆盖、现有 ECS 脚本与持续集成 |

API 先校验账号、输入和对象归属，再进入 Workflow；Workflow 校验阶段与预算后入队，Worker 执行 Provider。不要让页面直接调用模型，也不要用模型回复代替付费放行、归属或阶段校验。状态来源、幂等和 checkpoint 的取舍详见 [服务端说明](../server/README.md)。

## 分支、提交与评审

分支从最新 `main` 建立；并行任务限定自己的路径，避免跨轮重排。提交使用中文一行标题、作者 `chaw1 <97000945@qq.com>`，不含工具署名。暂存前检查状态，精确添加文件，提交前检查完整暂存差异。完整评审清单和门禁启用方式见贡献指南。

评审沿数据流检查：请求字段 → 校验 → Workflow → job payload → Provider → 持久化 → 输出 schema → App 类型与渲染；涉及阶段、重试、删除和付费确认时补对应行为测试。迁移既要覆盖空库升级，也要检查已有数据兼容，现有例子为 `server/tests/test_migrations.py`、`test_admin_migrations.py`。

## TypeScript 与 Python

TypeScript 使用 `app/tsconfig.json` 的 strict，组件/类型 PascalCase、函数/变量 camelCase、Hook `useXxx`；沿用单引号与分号。API 数据结构在 `app/src/api/types.ts`，新增外部输入先收窄类型，不随意扩散 `any`。导入排序、Hook 依赖和具体规则级别见下文规则与债务。

Python 函数/变量/模块 snake_case、类 CapWords、常量 UPPER_SNAKE_CASE；ruff 的 I 规则检查导入排序，E/F/UP/B 检查语法习惯与常见错误。`server/pyproject.toml` 设定行宽 100，实际启用规则以该配置为准。边界层补类型，复用 Pydantic schema；不运行全仓格式化改变无关代码。

App 业务失败使用 `app/src/api/client.ts` 的 `ApiError`（code/message/status），展示可恢复的中文提示；普通 REST 读/写/上传分别限时 20/60/120 秒，写入不自动重放。服务端使用 `app/errors.py` 的 `AppError`，`main.py` 统一输出 `{error: {code, message}}`，未知异常回通用中文信息；SSE 错误由事件传达。

新增网络调用必须指定超时，沿用 App 客户端及服务端 `providers.py` 的 httpx 访问方式；不能无限等待。供应商请求超时或结果未知时，不为通过检查盲目重复付费调用。重试次数、稳定去重键、attempt 和重放语义必须一起评审。

UI 新增颜色从 `app/src/theme.ts` 取，禁止在组件中新增硬编码色值。当前主题集中管理，但设计第 16 节的 JSON token 生成、组件拆分及其专属 ESLint 规则由设计系统轮实施，本轮不声称已有这些文件或命令。不得提交明文凭证、私钥、生产 `.env`，也不能在日志输出凭证或完整媒体签名 URL。

## 测试金字塔与命令

| 层级 | 命令（分别在对应目录执行） | 覆盖范围 |
|---|---|---|
| App 静态 | `npm run typecheck`、`npm run lint` | strict 类型与 ESLint |
| App 单元 | `npm test` | `tests/*.test.ts`，API/SSE、选图、草稿、发布等 |
| App 完整校验 | `npm run verify` | 类型、lint、单测、iOS/Android Expo 导出，输出 `app/verification/` |
| App 浏览器 | `PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/browsers" npm run test:e2e` | 默认排除 `live.spec.ts`，配置启动 :19301 假服务和 :19300 Web，390×844 视口 |
| 服务端静态 | `uv run ruff check .` | app、迁移、scripts、tests |
| 服务端单元与集成 | `REQUIRE_INTEGRATION=1 uv run pytest -q` | Provider Mock、图/Worker、鉴权、HTTP、PostgreSQL 队列和迁移 |
| 服务端闭环 | `uv run python scripts/e2e.py --mode mock` | 注册、上传、对话、出图、编辑、笔记、视频及媒体下载 |

从底层纯逻辑单测开始，涉及数据库/并发/HTTP 再用集成，跨页面和流程用假服务 Playwright。Mock 证据不等于真实模型质量，也不等于真机发布验收。真实模型与线上测试必须单独明确授权，本轮不运行。

服务端集成前启动本项目 Mock 栈：`cd server && docker compose up -d --build`。本机已有 API/Worker/PG 时复用，不抢占其他 worktree 的端口。测试固定本机 API :18080、PostgreSQL :18432，并校验 Mock；`REQUIRE_INTEGRATION=1` 使缺栈成为失败，避免静默跳过。迁移测试在独立随机 `outfit_test_*` 库执行，finally 只删除自己创建的库，禁止把已有库当残留清理。

## 门禁与 CI

现有 `.github/workflows/ci.yml` 在 push/PR 执行：server 任务提供 PostgreSQL 16、迁移、启动本地 Mock API/Worker 后跑 ruff/pytest；app 任务在 Node 22 执行类型、lint 和单测。CI 为只读仓库权限，不含部署。浏览器、镜像构建与覆盖率门禁在本轮后续步骤补齐，质量快照在实测后更新。

## 发布、健康与回滚

发布前先运行本地检查，核对迁移链及新旧 schema/数据兼容，保留数据库与媒体卷备份和上一个镜像 SHA。不得用容器删除或卷删除代替升级。

现有入口为 `cd server && ./deploy/deploy-ecs.sh`：本机构建 linux/amd64 镜像，以短提交 SHA 和 latest 标记，上传到配置的 ECS，再运行 Compose。它会连接远端，只有目标环境已明确授权才可执行；本轮仅检查脚本，不部署。

迁移在 `server/Dockerfile` 的启动命令里先执行 `alembic upgrade head`，成功后才启动 Uvicorn。部署脚本最后执行 compose ps；健康检查另外读取目标 `/api/health` 并检查 `ok` 与 Mock/真实模式符合预期，再验关键流程。Compose 已配置 API/PG healthcheck，`server/scripts/wait_health.py` 用于等待本机健康。健康接口检查数据库连接及配置，不验证上游模型服务可用性。

镜像回退需要人工将保留的旧 SHA 镜像标为 `outfit-agent-server:latest`，再用目标机已有的 `compose.yaml`、`compose.production.yaml`、`compose.image.yaml` 执行 `docker compose ... up -d`（完整参数同部署脚本），然后重复健康及关键流程检查。仓库没有自动回滚脚本；镜像回退不会自动撤销数据迁移。先判断旧版本是否兼容新 schema，不兼容则按已验证的数据备份恢复方案处理；不盲目执行有损 downgrade。

## 可观测与安全

请求 ID 由 `server/app/observability.py` 接收或生成并通过 `X-Request-ID` 返回；请求和模型事件为 JSON 行，包含 request_id、user_id、project_id、耗时和状态，模型事件还带模型名和估算成本。异常使用 `log_errors.log_exception`，文本经过脱敏；不要另开打印凭证或原始 SSE 内容的旁路。

请求计数持久化到 request_events，最近 24 小时 HTTP ≥400 或 SSE error 每请求计一次。管理端默认 `ADMIN_TOKEN` 为空而关闭，启用后使用独立会话；详见 `server/app/admin.py`、`runtime_settings.py`。观测数据和限流记录目前没有自动保留期，不能声称已有归档任务。

所有资产/项目/任务必须校验当前用户归属；媒体签名 URL 是可读凭证，备份、日志和截图都避免泄露签名。保留 `rate_limits.py` 的共享限流、上传类型/大小/像素上限和 `security.py` 的签名/鉴权。生产环境变量由部署环境注入，不从历史资料恢复或提交密钥。

## 规则与债务

基线 ESLint 使用 Expo flat 预设，Python ruff 启用 E/F/I/UP/B；新增规则只在现有代码零违规时设为 error。有历史违规的 ESLint 规则以 warn 暴露，ruff 使用精确文件/规则例外并记录原因，不修改 `app/src/**` 或 `server/app/**` 业务代码消债。本轮 lint 步骤实测后在此列出规则、文件位置和数量。

现有超时债务：`app/src/lib/media.ts:14` 的 Web 媒体下载直接使用 fetch，缺显式超时。本轮只记录，后续在业务轮次补可取消下载和错误反馈；新增代码仍遵守显式超时要求。
